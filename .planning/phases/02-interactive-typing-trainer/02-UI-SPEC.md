# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope of this phase's UI (per 02-CONTEXT.md + orchestrator scope note):** replaces the plain
> `<textarea>` capture surface from Phase 1 with the real trainer — a transparent-textarea-over-
> rendered-layer showing live per-character correctness coloring (correct/incorrect/pending), a
> custom caret, visible whitespace glyphs (space → `·`, newline → `↵`; **no tab glyph** — D-06
> amended: `normalize.ts` expands every tab to spaces before `Exercise.text` exists, so a literal
> tab can never appear in target text), and a Restart control. **Does not** compute or display
> WPM/accuracy/five-slowest-keys (Phase 3) and does not touch the paste box, upload control, or
> banners from Phase 1 (unchanged).
>
> **This EXTENDS `01-UI-SPEC.md`.** All spacing/typography/base-color tokens below are inherited
> unchanged unless explicitly called out as new. Do not re-derive the token foundation.

## Spacing Scale

Inherited unchanged from `01-UI-SPEC.md` (multiples of 4 only): `--space-xs` 4px, `--space-sm` 8px, `--space-md` 16px, `--space-lg` 24px, `--space-xl` 32px, `--space-2xl` 48px, `--space-3xl` 64px. No new spacing tokens needed.

**Layout for this phase:**
- Gap between the trainer surface and the Restart control: `--space-md` (16px).
- Gap between Restart and any adjacent meta text (e.g. a position readout, if included — see UI Considerations): `--space-sm` (8px).
- Restart button: same `.control` / `button.primary` treatment as Phase 1 (min 44px hit target via padding + line-height, not an off-scale margin).

**Exceptions** (rendering primitives, not layout spacing — same category as Phase 1's 1px borders / 44px hit-target floor):
- Custom caret rule width: 2px.
- Incorrect-status underline thickness: 2px, `text-underline-offset: 2px`.
- Character cells (the `<span>` per target character) carry **zero** padding/margin — spacing tokens apply to layout regions, never to individual glyphs, or column alignment breaks.

**No independent scroll container.** Unlike Phase 1's `.preview` (`max-height: 40vh; overflow: auto`), the trainer surface has **no** `max-height`/`overflow` of its own — content flows naturally in the page; a long exercise scrolls the page, not an inner box. This is a deliberate, locked decision (not left to executor discretion): a bounded scroll box would require keeping the invisible `<textarea>`'s `scrollTop` and the rendered layer's `scrollTop` in permanent sync on every scroll event (RESEARCH.md Pitfall 6's dual-layer-drift failure mode, in its scroll-position form) — a whole class of bug this phase avoids by construction rather than by discipline.

## Color

Theme continues to follow `prefers-color-scheme`, no manual toggle. All new tokens below are **additions** to `01-UI-SPEC.md`'s existing custom-property set — nothing in the Phase 1 palette is changed.

### New tokens — Light (default)

| Token | Value | Usage |
|-------|-------|-------|
| `--color-correct` | `#1C1C1A` (= existing `--color-text`) | Text color for a character typed correctly. **Not accent-green** — see rationale below. |
| `--color-pending` | `#5C5C57` (= existing `--color-text-muted`) | Text color for a not-yet-typed character. |
| `--color-incorrect` | `#C0362C` (= existing `--color-destructive`) | Text color for a character typed incorrectly (whether later corrected or not — see per-status rules below). |
| `--color-incorrect-bg` | `rgba(192, 54, 44, 0.14)` | Background tint behind an incorrect character's cell — pairs with `--color-incorrect` text + a 2px underline so the signal survives for colorblind users. |

### New tokens — Dark

| Token | Value | Usage |
|-------|-------|-------|
| `--color-correct` | `#E6EDF3` (= existing `--color-text`) | Same role as light. |
| `--color-pending` | `#8B949E` (= existing `--color-text-muted`) | Same role as light. |
| `--color-incorrect` | `#F85149` (= existing `--color-destructive`) | Same role as light. |
| `--color-incorrect-bg` | `rgba(248, 81, 73, 0.18)` | Same role as light. |

All four new tokens **alias existing, already-AA-verified Phase 1 values** (`--color-text`, `--color-text-muted`, `--color-destructive`) rather than introducing new hexes — no new contrast audit is needed for the text colors. The background tints are decorative (behind already-AA text), not themselves a text/background contrast pair.

### Why "correct" is not accent-green

A common typing-test convention colors correct characters accent/green. **Rejected here deliberately**: Phase 1's accent reserved-for list is explicit and exhaustive by design (60/30/10 discipline). An exercise can be up to ~100 KB — potentially tens of thousands of correctly-typed characters. Coloring all of them accent would blow the 10% accent budget by orders of magnitude the moment a user starts typing. Correct text instead uses the same primary text color already used for headings/body (`--color-correct` = `--color-text`) — "correct" reads as *normal, confirmed* text; only *pending* (dimmed) and *incorrect* (red-tinted) characters visually stand out from it.

### Accent reserved for (revised — extends Phase 1's exhaustive list by exactly one entry)

1. **Primary buttons** — "Load exercise" (Phase 1) and **"Restart exercise" (Phase 2, new)** — solid accent fill. Only one primary button is visible in a given view.
2. The focus ring on every interactive element — unchanged.
3. The capture `<textarea>`'s border while focused — unchanged. Note: in Phase 2 the textarea's *text* is transparent (D-01) but its *border* keeps this accent-while-focused treatment; text-color and border-color are independent properties.
4. **NEW — the custom trainer caret** (Phase 2): a solid `--color-accent`-colored 2px vertical bar at the current logical cursor position. This is the same "you are actively being recorded" semantic Phase 1 assigned to the focused-textarea border, now made precise at the character level.

Accent remains **never** used for correct-character text, whitespace glyphs, headings, or decorative fills — unchanged from Phase 1.

### Per-status rendering rule (precise, for executor parity)

| Status | Text color | Background | Underline |
|--------|-----------|------------|-----------|
| `pending` | `--color-pending` | none | none |
| `correct` | `--color-correct` | none | none |
| `incorrect` | `--color-incorrect` | `--color-incorrect-bg` | 2px, `--color-incorrect`, offset 2px |

**Whitespace glyph overlay rule (D-06):** when the target character is a space or newline, its glyph (`·` / `↵`) is rendered using the *same* text color the per-status rule above assigns (so a wrong space is still visibly red), but at `opacity: 0.55` on the glyph glyph text specifically — this is what "muted-color, overlaying the correct/incorrect palette rather than replacing it" (CONTEXT.md D-06) means in concrete CSS terms: the status color is never swapped out for a separate "glyph gray," it is dimmed in place. The `incorrect` background tint and underline are **not** dimmed — only the glyph character's own opacity is reduced, so an incorrect space still reads unambiguously as an error at a glance.

| Element | Copy |
|---------|------|
| Primary CTA | **Restart exercise** |
| Empty state heading | not applicable — Phase 2 always renders an already-loaded, non-empty `Exercise.text` (Phase 1 guarantees this before the trainer ever mounts) |
| Empty state body | not applicable, see above |
| Error state | not applicable — Phase 2 has **no** banner/toast/dialog error surface. Incorrect keystrokes are communicated exclusively via inline per-character coloring (see Color contract), never as a message. Do not add a "you made a mistake" banner. |

## UI Considerations

> Shape-rooted UI *state* coverage. Empty-state and error-state COPY live in `## Copywriting
> Contract` above; this section covers STATE coverage. Probe surfaces for this phase: E1 rendered
> per-character layer, E2 custom caret, E3 whitespace glyphs, E4 Restart control, E5
> backspace/correction flow, E6 Tab keydown. Resolved: **10 explicit, 3 backstop, 0 unresolved.**
> The planner MUST lift each row below into a plan's `must_haves`.

### Resolved — explicit (lift as `must_haves.truths` strings)

- Before the first keystroke, the rendered layer (E1) shows every character as `pending` (muted text, no background/underline) and the caret (E2) sits before index 0 — this is the trainer's natural initial state, not a distinct "empty" UI (no separate empty-state copy applies; the exercise itself is already loaded).
- While typing, each committed character immediately re-renders as `correct` or `incorrect` per the per-status rendering rule, and the caret (E2) advances to the new cursor position — matching TYPE-01/TYPE-02's "live... while typing" requirement.
- Free-correction (TYPE-02): advancing past a wrong character is never blocked; the character at the mistyped position keeps its `incorrect` styling (with underline) even after the cursor has moved further ahead, until backspace returns to it.
- Backspace (TYPE-03, E5) reopens exactly the previous position to `pending` (muted, no background) — it does not clear whether that position was "ever wrong" internally, but visually a re-pending character looks identical regardless of prior history (no "previously wrong" ghost mark).
- After backspacing and retyping correctly, a position that was `incorrect` and is now `correct` renders with the plain `correct` styling — no visual "this was corrected" badge (that distinction is data for Phase 3's accuracy metric, not a Phase 2 visual state).
- On completion (cursor reaches `text.length`), any remaining `incorrect` positions keep their full incorrect styling (red text + tint + underline) — completion is not conflated with "all correct"; nothing auto-clears or grays out uncorrected errors (per D-04, "complete" ≠ "all correct").
- Pressing Tab (E6, D-07 amended) produces **zero** visual change: no character is inserted, the cursor does not move, and no character renders differently — the keydown is fully absorbed (`preventDefault`) with no side effect other than keeping focus in the textarea. Do not build any "Tab was pressed" hint, glyph, or highlight.
- The Restart control (E4) is always visible once the trainer has mounted, uses the primary-button treatment (accent fill, 44px min hit target), and is reachable via Tab order after the capture surface, firing on Enter/Space/click.
- Clicking Restart resets `trainer/state.ts` to its initial all-`pending` state, moves the caret back to index 0, and refocuses the capture surface — visually indistinguishable from the trainer's first-load state (D-08's "no stale DOM/IME state survives").
- The invisible `<textarea>`'s native caret is never visible at any point (`caret-color: transparent` at all times) — the custom caret (E2) is the only cursor indicator a user ever sees, in every state (pending/typing/error/complete/restarted).

### Resolved — backstop (lift as `must_haves` flat scalars `{ statement, verification: backstop }`)

- statement: The custom caret (E2) blinks on a 1s cycle (~530ms visible / ~530ms hidden) while the window is focused and visible, renders solid (no blink) under `prefers-reduced-motion: reduce`, and renders solid (not hidden) — as a passive "timing is paused" cue — while the window is blurred or the tab is hidden (paired with D-09's active-time pause, though Phase 2 does not display a timer). — verification: backstop
- statement: A long unbroken line (e.g. minified code, no whitespace) wraps via `overflow-wrap: anywhere` in both the rendered layer and the invisible textarea identically, without ever requiring horizontal scroll — matches the "no independent scroll container" Spacing decision above and does not visually diverge from Phase 1's `.preview`'s different (no-wrap, horizontal-scroll) behavior in a way that looks like a bug. — verification: backstop
- statement: Arrow-key or mouse-click attempts to move the native selection within the trainer surface are silently re-synced back to the logical `cursor` position (RESEARCH.md Pattern 2) within one render frame, with no more than a brief, non-jarring visual flash of the caret at the attempted position — verification: backstop

### Not applicable

- `loading` — Phase 2 assumes a synchronously-loaded `Exercise` already in memory (Phase 1's contract); no async fetch/spinner state exists here.
- `zero-one-many` — exactly one exercise/session at a time, same as Phase 1.
- `overflow` beyond the long-line backstop above — the exercise size ceiling (100 KB) is already enforced at ingestion (Phase 1); Phase 2 renders whatever passed that gate.
- `partial` as a distinct list-partial state — not applicable; "partial completion" mid-typing is the normal `populated` state already covered above, not a degraded/partial-data view.

## Interaction Contract

**Everything below is additive to `01-UI-SPEC.md`'s Interaction Contract (theme, focus-ring, motion cap, no-layout-shift) — those rules are unchanged and still apply.**

- **Caret rendering:** the caret is a real, empty inline DOM element inserted into the character-span sequence immediately before the span at index `cursor` (flows with the monospace grid via normal document flow) — never positioned via `getBoundingClientRect()` or manual pixel math (RESEARCH.md Anti-Patterns; also untestable under Vitest/happy-dom's no-layout-engine limitation).
- **Caret source of truth:** derived solely from `trainer/state.ts`'s `cursor` output — never from `textarea.selectionStart` directly (D-10). After every commit, `textarea.selectionStart`/`selectionEnd` are forced back to `cursor` in a `useLayoutEffect`, per RESEARCH.md Pattern 2.
- **Arrow keys / click-to-reposition:** not blocked (no new `preventDefault` exception for these) — allowed, then silently corrected via the re-sync above (RESEARCH.md Open Question 2, resolved in favor of "re-sync, don't block" since it needs no new keydown carve-out and is fully reversible).
- **Tab key:** the one narrow, documented keydown exception for this phase — `preventDefault()`, no character insertion, no cursor movement (D-07 amended). This is a second carve-out alongside Phase 1's paste/drop exception in `capture.ts`, not a reopening of "no blanket preventDefault."
- **Whitespace glyphs must be typed explicitly:** a space/newline target position only advances on an actual committed space/newline character — there is no auto-skip or auto-indent (already excluded by REQUIREMENTS.md's Out of Scope table; reconfirmed here as a rendering-contract consequence).
- **Wrapping:** `white-space: pre-wrap; overflow-wrap: anywhere; tab-size: 4` (defensive — never actually reached, see Design System note) on both stacked layers, identically.
- **Motion:** caret blink (see UI Considerations backstop) is the only new animation this phase introduces; it is wrapped in `@media (prefers-reduced-motion: no-preference)` exactly like Phase 1's focus-ring/banner-fade transitions, and never exceeds the existing 150ms transition cap for any *other* motion (the blink itself is a distinct, longer 1s cycle by nature — a blink is not a "transition," it's the caret's baseline resting behavior).
- **No jitter in the hot path:** nothing about this phase's rendering may add work inside the `beforeinput`/`input`/`keydown` handlers themselves — `trainer/state.ts` recomputation and the resulting re-render happen in React's normal render cycle *after* the handler returns, never inside it (mirrors Phase 1's "keep the handler trivial" rule, now doubly important since Phase 2 adds a visible re-render on every keystroke).
