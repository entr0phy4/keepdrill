# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope of this phase's UI (per 05-CONTEXT.md + 05-RESEARCH.md):** two small, additive surfaces —
> (1) a **companion "adj. wpm" stat** in `ResultsView`, rendered beside the existing `wpm`/`accuracy`
> pair (D-08/D-09); (2) an **additional value** in `HistoryRow`, paired inline with the existing WPM
> column (D-10); and one new **form control** — (3) a native **language `<select>`** in `CorpusInput`,
> directly below the paste textarea, paste path only (D-11–D-14). No new component, no new page, no
> new view. Everything else (trainer surface, results panel structure, History view structure, upload
> path, Restart control, save-failure notice, view toggle) is unchanged.
>
> **This EXTENDS `01-UI-SPEC.md`, `02-UI-SPEC.md`, `03-UI-SPEC.md`, and `04-UI-SPEC.md`.** All
> spacing / typography / color tokens below are inherited unchanged unless explicitly introduced as
> new. Do not re-derive the token foundation. **No new token is introduced this phase.**

## Spacing Scale

Inherited unchanged from `01-UI-SPEC.md` (multiples of 4 only): `--space-xs` 4px, `--space-sm` 8px, `--space-md` 16px, `--space-lg` 24px, `--space-xl` 32px, `--space-2xl` 48px, `--space-3xl` 64px. **No new spacing tokens.**

### Layout — `ResultsView` third stat block (new)

- Add a third `.results-stat` block to the existing `.results-stats` grid (`src/index.css:344–356`), using the class verbatim — no new class, no new padding/gap value.
- **CSS change (resolves 05-RESEARCH.md Pattern 3's flagged open item):** bump `.results-stats`' `@media (min-width: 640px)` rule from `grid-template-columns: 1fr 1fr` to `grid-template-columns: 1fr 1fr 1fr`, so the three stats sit evenly on one row at desktop width instead of wrapping 2-then-1. Below 640px the existing single-column stack (`1fr`) is unchanged and already handles three items correctly. This is a one-line value change to an existing rule — not a new token, not a new selector.
- No new gap value: the existing `gap: var(--space-md)` (mobile) / `column-gap: var(--space-lg)` + `row-gap: var(--space-md)` (desktop) apply unchanged to the third block.

### Layout — `HistoryRow` companion value (new)

- No new element, no new class. The existing WPM `<span>` in `.history-row-primary` (`src/ui/HistoryView.tsx:50–52`) grows to hold both values inline, separated by a plain text `" / "` — no new gap token, no new flex/grid child. `.history-row-primary`'s existing `flex-wrap: wrap; column-gap: var(--space-md); row-gap: var(--space-xs)` (`src/index.css:454–461`) is unchanged and already handles the slightly longer span wrapping to a new line at narrow widths exactly like every other primary-line item.

### Layout — Language `<select>` (new, `CorpusInput.tsx`)

- Inserted as a new `<div style={{ display: 'grid', gap: 'var(--space-xs)' }}>` block, directly below the paste `<textarea>`'s block and above the upload `<input type="file">` block (D-11) — this is the exact same wrapper shape already used for the "Paste code or text" and "Or upload a file" blocks (`CorpusInput.tsx:112–124`, `126–148`), reused verbatim, not reinvented.
- Internal layout: `<label className="text-label">` → `--space-xs` (4px) gap → `<select>` — identical spacing rhythm to the two existing label+control pairs immediately above/below it.
- **The `<select>` itself gets `className="control"`** — the existing shared `button, .control { min-height: 44px; padding: var(--space-sm) var(--space-md); border: 1px solid var(--color-border); border-radius: 6px; background: var(--color-surface); color: var(--color-text); }` rule (`src/index.css:148–159`) already covers every visual property a select needs (border, radius, surface, 44px hit target). **No new CSS rule for the select control's box model or color** — only the class attribute is new.

### Spacing exceptions

None. No spacing exception is introduced this phase — the two stat-pairing changes reuse existing gap values exactly, and the select reuses the existing `.control` box model exactly.

Theme continues to follow `prefers-color-scheme`, no manual toggle. **Phase 5 introduces zero new color tokens and zero new accent usage.** Every color used below is an existing token from `01-UI-SPEC.md`.

| Role | Token | Usage in this phase |

| Accent (10%) | `--color-accent` | **Not used for the new stat values.** Only the pre-existing focus ring shows accent on the new select (already in the reserved list — see below). |

### Why the "adj. wpm" number is NOT accent-colored or threshold-colored

Same rule 03-UI-SPEC.md locked for `wpm`/`accuracy` and 04-UI-SPEC.md re-confirmed for `HistoryRow`: **no performance-threshold color-coding, no accent-highlighting for emphasis.** `symbolAdjustedWpm` renders in the exact same `--color-text` as `wpm` regardless of magnitude or of how much higher it is than net WPM — there is no "your adjusted score is better!" green tint, no color distinguishing it from net WPM other than its label. This is a direct, explicit extension of the locked rule (`REQUIREMENTS.md` Out of Scope: gamification), and matters specifically here because a companion "harder-adjusted" metric is exactly the kind of number a gamified UI would be tempted to highlight — deliberately rejected.

### Accent reserved for (unchanged from Phase 4 — no additions)

1. Primary buttons ("Load exercise", "Restart exercise") — unchanged.
2. The focus ring on every interactive element (now also including the new language `<select>`, via the existing global `:focus-visible` mechanism — no new CSS) — unchanged mechanism.
3. The capture `<textarea>`'s border while focused — unchanged.
4. The custom trainer caret — unchanged.

Phase 5 adds no fifth entry. Accent stays exactly as scarce as Phase 4 left it.

## Interaction Contract

**Everything below is additive to `01–04-UI-SPEC.md`'s Interaction Contract (theme, focus-ring, 150ms motion cap, no-layout-shift, caret rendering, display-layer rounding, hide-don't-unmount) — those rules are unchanged and still apply.**

- **Language `<select>`:** a native, uncontrolled-by-default HTML `<select>` with `value`/`onChange`
  wired to component state (`pasteLanguage`, defaulting to `'plaintext'`, D-13). Activated by click
  (opens native OS/browser dropdown) or keyboard (arrow keys while focused, native `<select>`
  semantics — no custom keyboard handling is added). The focus ring is the existing accent
  `:focus-visible` outline — unchanged mechanism, no new CSS. Selecting a value does **not** submit,
  load, or trigger any side effect beyond updating the local state that `handleLoad` reads when
  "Load exercise" is next clicked (D-14 — never blocking, never auto-submitting).
- **No motion introduced:** neither the new stat blocks nor the select have any transition, fade,
  or animation of their own. `ResultsView`'s existing panel-level fade-in (03-UI-SPEC.md) covers the
  third stat block automatically since it fades in as part of the same panel, not as a separate
  animated element. No count-up/number animation on either new WPM value (unchanged "no gamification"
  motion rule).
- **No layout shift:** the `.results-stats` grid-column change (1fr·1fr → 1fr·1fr·1fr) is a static
  CSS rule, not a runtime toggle — there is no moment where two stats render before a third pops in;
  all three render together in the same pass the results panel always has (D-08, "always shown...
  never conditionally hidden"). The select renders from `CorpusInput`'s first paint alongside the
  paste textarea and upload input — no reflow of either existing block when the picker's value
  changes.
- **Rounding discipline (executor note):** `Math.round()` is applied only at the two display call
  sites (`ResultsView.tsx`, `HistoryView.tsx`) — never inside `symbol-density.ts` or `metrics.ts`.
  Same rule as every existing metric (03-UI-SPEC.md, 04-UI-SPEC.md).
- **No new keyboard exceptions:** the select uses 100% native `<select>` keyboard behavior (arrow
  keys, type-ahead, Enter/Escape to commit/dismiss the native dropdown) — no `preventDefault`, no
  custom keydown handling, no interaction with the existing capture-surface Escape-to-restart
  shortcut (Phase 2), which remains scoped to the trainer `<textarea>` only.
