# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope of this phase's UI (per 04-CONTEXT.md + 04-RESEARCH.md):** three new surfaces —
> (1) a header **view toggle** between the existing trainer view and a new History view (D-07);
> (2) the **History view**: a newest-first, read-only list of past sessions with an explicit
> empty state and a loading state (PERS-02, D-09..D-14); (3) a **save-failure notice** rendered
> inline near the results panel, `role="status"`, dismissible (PERS-03, D-15..D-17).
> The trainer subtree is **hidden, never unmounted**, when History is showing (D-08).
> Everything else (trainer surface, results panel, Restart control, banners) is unchanged.
> Out of scope: per-session drill-down / clickable rows (ANLY-07, D-13), delete / clear-history
> controls (deferred), any trend or chart view (Phase 6), symbol-adjusted WPM (Phase 5).
>
> **This EXTENDS `01-UI-SPEC.md`, `02-UI-SPEC.md`, and `03-UI-SPEC.md`.** All spacing / typography /
> color tokens below are inherited unchanged unless explicitly introduced as new. Do not
> re-derive the token foundation. No new token is introduced this phase.

## Spacing Scale

Inherited unchanged from `01-UI-SPEC.md` (multiples of 4 only): `--space-xs` 4px, `--space-sm` 8px,
`--space-md` 16px, `--space-lg` 24px, `--space-xl` 32px, `--space-2xl` 48px, `--space-3xl` 64px.
**No new spacing tokens.**

### Layout — header view toggle (new)

- The existing `<header>` (currently just `<h1>keebdrill</h1>`) becomes a flex row:
  `display: flex; align-items: baseline; justify-content: space-between; gap: var(--space-md); flex-wrap: wrap`.
  `<h1>` stays left; the view-toggle `<nav>` sits right, wrapping under the title on narrow widths.
- The toggle `<nav>` is an `inline-flex` with `gap: var(--space-xs)` between its two buttons.
- Both toggle buttons render from first paint (see Interaction Contract — no layout shift); the
  toggle occupies its space whether or not an exercise is loaded.
- Toggle buttons keep the existing global `button` sizing (`min-height: 44px`,
  `padding: var(--space-sm) var(--space-md)`) — they are real controls, not a spacing exception.

### Layout — History view (new)

- Renders in the **same main-grid slot** the trainer subtree occupies (the `<main>` grid keeps its
  existing `gap: var(--space-lg)`). When `view === 'history'`, the trainer wrapper `<div>` is set to
  `display: none` and `<HistoryView>` renders after it.
- `<HistoryView>` internal: `<h2>History</h2>` → `var(--space-lg)` (24px) gap → list / empty / loading region.
- **List** (`.history-list`, an `<ol>`): `display: grid; gap: var(--space-sm)` (8px between rows);
  `list-style: none; margin: 0; padding: 0`.
- **Row** (`.history-row`, an `<li>`): bordered Secondary-surface card — `background: var(--color-surface)`,
  `border: 1px solid var(--color-border)`, `border-radius: 6px`, `padding: var(--space-md)` (16px);
  internal `display: grid; gap: var(--space-xs)` (4px) between the two row lines.
  - **Primary line** (`.history-row-primary`): relative date, WPM, accuracy —
    `display: flex; flex-wrap: wrap; column-gap: var(--space-md); row-gap: var(--space-xs); align-items: baseline`.
  - **Meta line** (`.history-row-meta`): source label, language tag, exercise length, slowest-key chip —
    `display: flex; flex-wrap: wrap; align-items: center; column-gap: var(--space-md); row-gap: var(--space-xs)`.
- **Empty / loading region** (`.history-empty` / `.history-loading`): a single muted `<p>`,
  `margin: 0`, `padding-block: var(--space-md)`. No card, no border.
- No independent scroll container on `<HistoryView>` — the list grows the page downward and scrolls
  with normal page flow (D-18 keep-forever; no virtualization in Phase 4 — see UI Considerations backstop).

### Layout — save-failure notice (new)

- Renders **between `ResultsView` and the Restart button** in DOM/visual order:
  trainer surface → results panel → **save-failure notice** → Restart button.
- Gap above and below: `var(--space-md)` (16px) — the trainer wrapper's existing grid `gap`.
- Container reuses the existing `.banner .banner--warning` box (`padding: var(--space-sm) var(--space-md)`,
  `border-radius: 4px`, left border 3px) — no new padding values.
- Internal layout: `display: flex; align-items: flex-start; gap: var(--space-sm); justify-content: space-between`
  — message text left, dismiss `×` button right.

### Spacing exceptions

| Exception | Value | Rationale |
|-----------|-------|-----------|
| Save-notice dismiss button (`.save-failed-dismiss`) | ~24px glyph target, `padding: var(--space-xs)`, `background: transparent`, `border: 0`, `min-height: 0` | Exempt from the 44px control floor — same exception class as Phase 3's `.key-chip`. Meets WCAG 2.5.8 (24×24 minimum); `--space-xs` padding widens the effective hit area. `aria-label="Dismiss notice"`. |
| Chip padding (language tag + slowest-key chip) | `var(--space-xs)` vertical / `var(--space-sm)` horizontal | Reuses Phase 3's `.key-chip` internal padding verbatim — a compact `<kbd>`-style badge, not a control. |
| Chip border | 1px `var(--color-border)` | Same weight as all existing borders. |

## Color

Theme continues to follow `prefers-color-scheme`, no manual toggle. **Phase 4 introduces zero new color
tokens and zero new accent usage.** Every color below is an existing token from `01-UI-SPEC.md`.

| Role | Token | Usage in this phase |
|------|-------|----------------------|
| Dominant (60%) | `--color-bg` | Page background — unchanged; also the background of chips *inside* history rows (so a bordered chip stays legible against the row's Secondary surface) |
| Secondary (30%) | `--color-surface` | History row cards; the **active** view-toggle button fill |
| — border | `--color-border` | Row borders; chip borders; view-toggle button borders; the inactive-underline of the toggle |
| — text primary | `--color-text` | Relative date, WPM value, accuracy value, chip glyph, active toggle label |
| — text muted | `--color-text-muted` | Unit labels, source label, language-tag text, exercise length, empty/loading copy, inactive toggle label |
| Warning surface | `--color-warning-surface` | Save-failure notice background (via existing `.banner--warning`) |
| Warning text | `--color-warning-text` | Save-failure notice text + lead + the `×` dismiss glyph |
| Accent (10%) | `--color-accent` | **Not used for any new element.** Only the pre-existing focus ring (already in the reserved list) shows accent on the new controls. |
| Destructive | `--color-destructive` | **Not used.** No destructive action exists this phase (rows are inert, D-13; delete/clear deferred). A failed save is a *warning*, not a destructive event — it matches the existing degraded-timing banner's treatment. |

### Why the save-failure notice is `warning`, not `destructive`

The existing convention (`Banners.tsx`) already uses `.banner--warning` (yellow) for the
"degraded timing" advisory and reserves `--color-destructive` (red) strictly for genuinely
destructive UI. A session that failed to persist is non-blocking, non-fatal, and not the user's
fault — warning-yellow with a "Heads up" lead is the exact right register and reuses an existing
style. Red would over-signal.

### Why the active view toggle is NOT accent-colored

Same reasoning as Phase 3's rejection of accent-highlighted stat numbers: the accent reserved-for
list is exhaustive by design (60/30/10 discipline). A tab/segment "selected" state is a classic
place teams reach for accent; here the active option is instead distinguished by a Secondary-surface
fill + weight 600 + primary (not muted) text, with the inactive option flat/transparent + muted.
This keeps accent as scarce as Phase 3 left it.

### Accent reserved for (unchanged from Phase 3 — no additions)

1. Primary buttons ("Load exercise", "Restart exercise") — unchanged.
2. The focus ring on every interactive element (now also the two view-toggle buttons and the
   dismiss button) — unchanged mechanism.
3. The capture `<textarea>`'s border while focused — unchanged.
4. The custom trainer caret — unchanged.

Phase 4 adds no fifth entry.

### No performance-threshold color-coding

History row WPM and accuracy values render in `--color-text` regardless of magnitude — no
good/green, no bad/red banding, no per-row "personal best" highlight. Explicit locked rule
(carried from 03-UI-SPEC.md, REQUIREMENTS.md Out of Scope: gamification). D-10 also forbids any
flash/highlight on the newly-added row.

## UI Considerations

> Shape-rooted UI *state* coverage. Empty-state and error-state COPY live in `## Copywriting Contract`
> above; this section covers STATE coverage and references those rows. Probe surfaces for this phase:
> **H1** header view toggle · **H2** History view container + heading · **H3** loading state
> (`useLiveQuery` `undefined`) · **H4** empty state (`[]`) · **H5** populated list · **H6** an
> individual history row and its seven fields · **H7** save-failure notice · **H8** the hidden
> (not unmounted) trainer subtree.
>
> Resolved: **12 explicit, 5 backstop, 1 unresolved.** The planner MUST lift each row below into a
> plan's `must_haves` (`⚠ unresolved` → surface as an explicit planner assumption).

### Resolved — explicit (lift as `must_haves.truths` strings)

- The header view toggle (H1) always renders exactly two options, `Trainer` and `History`, both
  present from first paint regardless of whether an exercise is loaded; `Trainer` is the active
  option on initial load. Switching is a synchronous `useState` view flip — no route change, no URL
  change, no async, no spinner.
- The active toggle option carries `aria-current="page"` and the active visual treatment
  (`--color-surface` fill, weight 600, `--color-text`); the inactive option is transparent-background,
  weight 400, `--color-text-muted`. Exactly one option is active at any time.
- Switching to the History view sets the trainer wrapper `<div>` to inline `display: none` and
  renders `<HistoryView>` in the same main-grid slot; the trainer subtree is **never unmounted**
  (D-08). Switching back to `Trainer` restores `display: grid` — in-progress typed text, caret
  position, per-character coloring, the `<textarea>` value/IME state, and the module-level capture
  buffer are all intact; no confirm dialog is shown and no progress is lost.
- Because the trainer `<textarea>` is `display: none` while History is showing, it cannot receive
  keystrokes — so an exercise completion (and its persist write) cannot occur while the History view
  is visible. There is no "row appears while I'm watching" animation to design (D-10).
- `useLiveQuery` returns `undefined` on the first render before the IndexedDB promise resolves
  (H3): the view renders the loading line ("Loading history…"), **not** the empty state.
  `undefined` (loading) and `[]` (empty) are never conflated (04-RESEARCH.md Pitfall 5).
- When the query resolves to `[]` (H4), the view renders the empty-state body copy from the
  Copywriting Contract in place of the list; the `<h2>History</h2>` still renders above it.
- When the query resolves to a non-empty array (H5), the view renders an `<ol>` of rows in
  newest-first order (`startedAt` descending, D-09); ordering is stable and matches the relative
  dates the user reads top-to-bottom.
- Finishing an exercise does nothing to the History view (D-10): the app stays on the results
  screen, there is no auto-navigation to History, and when the user next opens History the new row
  is simply present with no flash, highlight, or scroll-into-view. If History is opened shortly
  after a completion, the live query surfaces the new row automatically once the fire-and-forget
  write resolves — no manual reload (D-09).
- History rows (H6) are inert: no `onClick`, no `href`, no `tabindex`, not focusable, no
  pointer-cursor, no hover elevation or affordance implying interactivity (D-13). The only hover
  behavior is the native `title` tooltip on the relative-date span.
- A history row whose `metricsSnapshot.slowest5` is empty (short exercise) renders every other
  field normally and simply omits the slowest-key chip — a partial metrics snapshot is a valid,
  expected row shape, never a row-level error (mirrors Phase 3's slowest-keys rule).
- A slowest-key chip whose character is a space or newline renders `·` / `↵` via `glyphFor` —
  never a blank, invisible, or literal-whitespace chip.
- The source label (H6) is never blank: `exercise.sourceRef` filename for uploads that have one,
  `Uploaded file` for uploads without one, `Pasted snippet` for pasted corpus.
- The save-failure notice (H7) renders only when `metrics !== null && saveFailed === true`,
  positioned between the results panel and the Restart button, with `role="status"`. It never
  blocks, delays, or covers the results panel — the results panel has already rendered
  synchronously before the write is even fired (D-04 / PERS-03). It carries a `×` dismiss button
  (`aria-label="Dismiss notice"`); dismissing it, or loading/restarting any exercise, clears
  `saveFailed` and unmounts the notice.

### Resolved — backstop (lift as `must_haves` flat scalars `{ statement, verification: backstop }`)

- statement: A long source-label filename (or an unexpectedly long `exercise.language` string)
  wraps or ellipsizes within `.history-row` and never causes horizontal overflow or a horizontal
  page scrollbar. — verification: backstop
- statement: With hundreds of stored sessions (D-18 keep-forever; ~months of daily use), the
  History `<ol>` renders as a plain non-virtualized list that scrolls within normal page flow
  without layout breakage; render performance is acceptable at single-user daily-use scale
  (04-RESEARCH.md §Data Model). — verification: backstop
- statement: If a stored session's metrics must be recomputed on read (`schemaVersion` mismatch —
  dormant until Phase 5) and the recompute hits a zero-elapsed-time edge, the row's WPM renders the
  engine-guarded `0 wpm`, never `NaN wpm` or `Infinity wpm` (same display-layer guard as Phase 3).
  — verification: backstop
- statement: The save-failure notice appears/disappears using only the existing `.banner` 150ms
  opacity transition (already wrapped in `@media (prefers-reduced-motion: no-preference)` in
  `index.css`); its removal contracts the page upward and causes no layout shift to the results
  panel or the trainer surface above it (same rule as Phase 1 banner appearance). — verification: backstop
- statement: Toggling `Trainer → History → Trainer` after typing a few characters preserves the
  exact caret index and per-character coloring in the trainer surface (the `display:none`
  hide-not-unmount contract, D-08). — verification: backstop

### Resolved — unresolved (planner treats as an explicit assumption)

- ⚠ The `display:none` hide-not-unmount approach (D-08 / 04-RESEARCH.md Open Question 1 / Assumption
  A1) is believed sufficient to preserve in-progress capture state, but `happy-dom` cannot verify
  uncontrolled-`<textarea>` selection/IME behavior after visibility toggling. **Planner assumption:**
  a real-browser (Chromium-first) or Playwright verification task is added; if hiding proves
  insufficient, the fallback is lifting the capture buffer into a ref that survives remount and
  allowing the trainer to unmount. This affects implementation strategy, not the visual contract.

### Not applicable

- `error` beyond the save-failure notice — reads via `useLiveQuery` have no user-facing failure
  mode worth surfacing in Phase 4; a corrupt/unavailable IndexedDB on the read path degrades to the
  loading or empty state, and that is acceptable (no separate "couldn't load history" copy this
  phase).
- `loading` for anything except the initial `useLiveQuery` resolve — subsequent live updates are
  diffed in by Dexie with no intermediate loading flash.
- destructive / confirmation states — no delete, clear, or row action exists this phase.
- `zero-one-many` beyond the empty/loading/populated split above — there is exactly one History
  view and one save-failure notice; only the row list varies in cardinality, already covered.

## Interaction Contract

**Everything below is additive to `01/02/03-UI-SPEC.md`'s Interaction Contract (theme, focus-ring,
150ms motion cap, no-layout-shift, caret rendering, display-layer rounding) — those rules are
unchanged and still apply.**

- **View toggle:** two native `<button>`s. Activated by click / Enter / Space (native button
  semantics). The focus ring is the existing accent `:focus-visible` outline — unchanged mechanism.
  No programmatic focus movement on view switch: focus stays on the toggle button the user
  activated. Switching to History does not auto-focus the list; switching back to Trainer does not
  steal focus back into the `<textarea>`.
- **Hide, don't unmount (D-08):** the trainer wrapper's visibility is toggled by setting its inline
  `display` between `grid` and `none` directly — **not** via the HTML `hidden` attribute (defeated
  by the element's inline `display`, 04-RESEARCH.md Pitfall 6) and **not** via conditional unmount
  (`{view === 'trainer' && …}`), which would drop the uncontrolled `<textarea>` node and its
  caret/IME state.
- **History rows:** receive no focus and no keyboard interaction (inert, D-13). The relative-date
  `title` tooltip is the only hover behavior.
- **Save-failure notice dismiss:** the `×` button is activated by click / Enter / Space; on dismiss
  `saveFailed → false`, the notice unmounts, and the page contracts upward with no layout shift
  to anything above it. The notice is also cleared (set `false`) at the start of `handleComplete`
  and in `handleLoad` / `handleRestart`, so a stale notice never survives a fresh run.
- **Motion:** no new motion is introduced. The notice reuses the existing `.banner` 150ms opacity
  transition. The view switch is an **instant** swap — no slide, no fade, no cross-dissolve. The
  History list has **no** row-entry animation (D-10 forbids flash/highlight). No count-up on the
  row numbers.
- **No layout shift:** both toggle labels render from first paint so the header never reflows when
  the active state changes. The History view replaces the trainer subtree in the same `<main>`
  grid slot, so switching views does not move the header or the corpus input above it.
- **Rounding discipline (executor note):** `Math.round()` is applied only in the History row render
  (WPM, accuracy) — never inside `metrics.ts`, never inside the `resolveMetrics` recompute helper,
  and never before ranking `slowest5`. Same rule as `ResultsView`.
- **`role="status"` on the notice** (not `role="alert"`) — a failed background save is not urgent
  enough to interrupt a screen-reader user mid-sentence; polite announcement matches `Banners.tsx`
  and `ResultsView`.
