<objective>
Add a code-symbol-density-aware companion WPM to the existing net-WPM metric, computed as a
pure session-level multiplier on the target exercise's overall symbol density (D-04/D-05), and
surface it as a second, always-visible number next to net WPM on both the results screen
(`ResultsView`) and every history row (`HistoryRow`) — never a replacement, never conditionally
hidden (D-08).

**Assumption-delta decision (recorded per orchestrator instruction): add-alongside, not
promote.** `symbolAdjustedWpm` is an ADDITIVE companion field on `MetricsResult`. `wpm` remains
the primary/required field and is never demoted, replaced, or made optional. This is the locked
design (CONTEXT.md D-08, "companion metric, never a replacement" — matches the existing
Monkeytype raw/net precedent). The "alongside" wording in the phase goal is a companion-metric
signal, not a second-identity/second-source-of-truth signal — no promote is warranted.

Purpose: satisfies ANLY-01 (symbol-adjusted WPM, results screen + history) and establishes the
D-06 schema-version-2 recompute-on-read path so every pre-existing session in history gains the
new metric with zero migration.

Output: `src/metrics/symbol-density.ts` (new pure module) + `src/metrics/symbol-density.test.ts`
(new golden-case tests), modified `src/metrics/metrics.ts` + `src/metrics/metrics.test.ts`
