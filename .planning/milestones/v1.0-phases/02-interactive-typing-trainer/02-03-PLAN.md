<objective>
Close the one blocking gap from 02-VERIFICATION.md (independently confirmed by 02-REVIEW.md's WR-1):
`CaptureSurface.tsx`'s caret-resync `useLayoutEffect` is keyed on `[cursor]` alone, so it never
corrects native-selection drift caused by ArrowLeft/ArrowRight/Home/End or a mouse click — none of
which change `cursor` or trigger any other re-render. Concrete consequence: after drift moves the
native selection to a boundary (e.g. index 0), a subsequent Backspace can produce zero `beforeinput`
events in a real browser, silently dropping a keystroke — a real violation of TYPE-01 (caret
integrity) and TYPE-03 (backspace-to-correct).

Also closes the related, non-blocking WR-2 finding: `handleKeyDown`'s Escape/Tab branch has no
`isTrusted` guard, unlike every input handler in `src/capture/capture.ts` (T-01-04 convention) — a
script-dispatched synthetic Escape could otherwise trigger Restart and wipe the user's in-progress
session.

Purpose: make the D-10/T-02-04 caret-resync mitigation actually hold for every interaction that can
move native selection, not only for committed keystrokes, and bring `handleKeyDown` into line with
the codebase's established input-trust convention.

Output: no new files, no new exported symbols — this plan only modifies the two files already
listed above (`src/ui/CaptureSurface.tsx`, `src/ui/CaptureSurface.test.tsx`). Both fixes are wholly
contained inside `CaptureSurface`'s existing render body and its test suite; `src/trainer/state.ts`,
`src/trainer/active-time.ts`, `src/ui/App.tsx`, and `src/index.css` are untouched by this plan.
</objective>
